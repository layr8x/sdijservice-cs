# 상담 수집 확장 프로그램

카카오 파트너센터에 로그인된 직원의 크롬이 5분마다 상담 내용을 읽어 사내 데이터베이스에 모읍니다.

## 왜 이 방식인가

카카오는 상담 대화를 내보내는 공식 방법을 제공하지 않습니다. 그래서 사람이 로그인한 브라우저
세션을 빌려 읽는 것 외에 방법이 없습니다.

예전 방식은 그 세션을 담당자 한 명의 맥북에서 꺼내 썼습니다. 그 사람이 자리를 비우거나 퇴사하면
수집이 멈춥니다. 실제로 그 문제로 5일간 수집이 중단된 적이 있습니다.

이 확장은 그 의존을 없앱니다. **파트너센터 권한이 있는 직원 누구든 설치해 두면, 그 사람이
출근해서 크롬을 켜는 동안 수집이 돌아갑니다.** 여러 명이 설치해도 됩니다. 같은 내용을 두 번 넣어도
덮어쓰기라 중복이 생기지 않고, 오히려 한 사람이 자리를 비워도 다른 사람 쪽에서 계속 모입니다.

## 설치 (직원용, 한 번만)

1. 크롬 주소창에 `chrome://extensions` 를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누르고, 이 `extension` 폴더를 선택합니다.
4. 크롬 오른쪽 위 확장 아이콘에서 이 확장을 눌러 **연결 설정**을 폅니다.
5. 관리자에게 받은 **수집 서버 주소**와 **수집 키**를 넣고 저장합니다.
6. `business.kakao.com` 에 로그인합니다. 끝입니다.

설정값은 그 브라우저에만 저장되고, 한 번 넣으면 다시 넣을 일이 없습니다.

> 사내 PC 관리 정책상 개발자 모드가 막혀 있다면, 관리자가 Chrome 정책(`ExtensionInstallForcelist`)으로
> 배포하거나 Chrome 웹스토어에 비공개로 올려야 합니다.

## 확장 아이콘을 눌렀을 때

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 정상 | 잘 모으고 있음 | 없음 |
| 새 내용 없음 | 정상. 새로 들어온 상담이 없을 뿐 | 없음 |
| 로그인 필요 | 파트너센터 로그인이 풀림 | "파트너센터 열기"를 눌러 로그인 |
| 설정 필요 | 서버 주소·키가 비어 있음 | 연결 설정에 값 입력 |
| 오류 | 그 외 문제 | 메시지를 관리자에게 전달 |

## 관리자 준비 사항

1. **수집 키 만들기** — Supabase SQL Editor에서 한 번 실행합니다.

   ```sql
   insert into kakao_partner_secrets (key, value)
   values ('kakao_ingest_token', encode(gen_random_bytes(24), 'hex'))
   on conflict (key) do nothing;

   select value as 수집키 from kakao_partner_secrets where key = 'kakao_ingest_token';
   ```

2. **수집 함수 배포** — `supabase/functions/kakao-ingest` 를 배포합니다.
   로그인 검사가 아니라 위 수집 키로 인증하므로 `verify_jwt` 는 꺼야 합니다.

   ```bash
   supabase functions deploy kakao-ingest --no-verify-jwt
   ```

3. 직원들에게 **수집 서버 주소**(`https://<프로젝트>.supabase.co/functions/v1/kakao-ingest`)와
   위에서 뽑은 **수집 키**를 전달합니다.

## 보안상 알아둘 것

- **수집 키는 확장 안에 들어가므로 유출될 수 있다고 전제했습니다.** 그래서 이 키로 할 수 있는 일은
  상담 내용 넣기 하나뿐입니다. 읽기, 삭제, 다른 표 접근은 되지 않습니다. 유출이 확인되면 위 SQL로
  값만 새로 만들면 됩니다.
- **개인정보 가리기는 확장이 아니라 서버가 합니다.** 확장은 직원 PC에서 도는 프로그램이라 낡거나
  바뀔 수 있어, 무엇을 저장할지 판단하는 일을 맡기지 않았습니다. 이름·전화번호·이메일·카드번호·
  주민번호는 서버에 저장되기 직전에 가려집니다.
- 확장은 `business.kakao.com` 과 Supabase 두 곳에만 접근합니다. 다른 사이트는 보지 않습니다.
- 카카오 계정의 비밀번호는 어디에도 저장하지 않습니다. 이미 로그인된 세션을 쓸 뿐입니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `manifest.json` | 확장 정의 (권한, 5분 주기 실행) |
| `background.js` | 5분마다 수집을 돌리고 결과 상태를 기록 |
| `collector.js` | 실제 수집 동작 (카카오 조회 → 서버 전송) |
| `popup.html` / `popup.js` | 아이콘을 눌렀을 때 보이는 상태 화면 |

## 유실을 막는 규칙 (수정 시 주의)

`collector.js` 에는 되돌리면 안 되는 규칙이 하나 있습니다.

**대화 내용을 못 가져온 대화방은, 그 방의 정보를 서버로 보내지 않습니다.** 보내면 서버가 "여기까지
받았다"고 기록해 버려서, 다음 실행이 "변경 없음"으로 판단하고 그 상담을 영영 안 가져옵니다.
원본 시스템에서 이 순서를 어겨 646개 대화방의 첫 메시지가 유실된 적이 있습니다.
